Store operations

This runbook covers the Mac App Store and universal iPhone/iPad products. The direct Mac target remains separate. Ayush owns submission, support, incident triage, and the final release decision. A passing build or local package inspection does not establish signed-device behavior or App Store acceptance.

Prepare the exact artifact

Run development tests with Debug configuration and isolated derived data. Archive is a separate, deliberate production packaging step after reviewed code is committed and the all-target CI matrix passes. Use a new output directory for each attempt. Choose the marketing version and per-platform build number from the current App Store Connect record; examples below are placeholders, not reserved numbers. The explicit build settings apply to the app and embedded extensions together.

Distribution/release.sh archive --platform macos --version VERSION --build BUILD /absolute/path/mac-artifact
Distribution/release.sh archive --platform ios --version VERSION --build BUILD /absolute/path/ios-artifact
Distribution/release.sh verify /absolute/path/mac-artifact

The archive command uses the Store scheme, exports locally with app-store-connect, disables automatic version/build renumbering, and never enables provisioning updates. Install correct profiles/certificates separately if Xcode reports missing authorization. It records the commit, Xcode, command, archive/export hashes, signed identities, entitlements, architectures, profile expiration, privacy manifests, and matching executable/dSYM UUIDs. No step modifies project versions, commits, pushes, publishes a GitHub release, or submits App Review.

Preserve the whole output directory, including artifact.json, Vellum.xcarchive, export, and symbols. A failed attempt is retained for diagnosis and cannot pass verify without its completed manifest. Rebuilds create a new candidate and invalidate prior acceptance; they never replace the candidate already tested.

Validate, then upload unchanged

These commands contact Apple. Run them only when the operator intends that action. Set VELLUM_ASC_PASSWORD to an app-specific password in the shell without placing its value in shell history, logs, or source. Supply --provider when the account has multiple providers. Xcode 26.6+ altool resolves the environment reference.

Distribution/release.sh validate /absolute/path/mac-artifact --username APPLE_ID
Distribution/release.sh upload /absolute/path/mac-artifact --username APPLE_ID

Validation records a success receipt only after Apple's command succeeds. Upload requires that receipt and rechecks the manifest, package, archive and symbols. Both send a private copy whose digest matches the recorded export. They never invoke archive or export. Logs and receipts stay beside the artifact; protect them as account/operational records and redact them before sharing. Check App Store Connect processing and delivery status after a network failure before retrying: interrupted delivery can succeed remotely without a local receipt.

Upload is not release. Select the processed build in App Store Connect, stage with TestFlight, record the exact version/build and receipt against the artifact digest, then complete review and release controls there. Preserve the previous known-good artifact and its symbols. Halt a phased release and ship a corrective update for a regression; an older uploaded build cannot be assumed to provide an automatic rollback for installed users.

Go/no-go evidence

Attach the artifact digest and actual device/OS/build to each result in release issues. Require two signed devices to prove first cloud sync, offline conflict edits/deletions, eviction/redownload, account change and PDF/annotation/note/attachment/chat continuity. Require Safari sharing, extension termination, oversized-page fallback, widget routing, and cold locked-device integration refresh. Complete VoiceOver, largest text, keyboard navigation, touch/pointer targets, iPad rotation/Split View and the representative PDF/archive corpus. Simulator tests do not close physical-device gates.

Stage the same processed build with TestFlight; record launch/interaction/memory measurements on supported hardware and unresolved regressions. Release only after blocking issues and review findings are closed with evidence. For incidents, collect app version/build, OS/device class, reproduction steps and redacted diagnostics; request synthetic examples before asking for user documents. Never request tokens, entire libraries, or unredacted conversations by default.

Apple references: build upload and validation; web-content ATS exception. Export options are checked against the installed xcodebuild -help.
