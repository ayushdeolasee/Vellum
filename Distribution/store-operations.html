Release operations

macOS uses Developer ID distribution and Sparkle updates through Vellum Mac. iPhone/iPad use the App Store through Vellum. Ayush owns submission, support, incident triage and release decisions. Local fixtures and package inspection do not establish signed-device behavior, notarization, update installation or App Store acceptance.

Local preparation

Run development builds and tests with Debug configuration and isolated derived data. Archive is a separate, explicit production packaging operation after reviewed source is committed. Use a new output directory per candidate. The tools never bump source versions, commit, push, rebuild during promotion or enable provisioning updates. Install authorized certificates/profiles separately; this tooling does not access portal capabilities.

python3 -m venv ~/.codex/venvs/vellum-release
~/.codex/venvs/vellum-release/bin/python -m pip install -r Distribution/requirements-release.txt
export VELLUM_RELEASE_PYTHON=~/.codex/venvs/vellum-release/bin/python

Distribution/release-macos.sh archive --version VERSION --build BUILD \
  --signing-identity 'Developer ID Application: EXACT CERTIFICATE NAME (9DCG97VASG)' \
  /absolute/path/mac-artifact
Distribution/release.sh archive --platform ios --version VERSION --build BUILD /absolute/path/ios-artifact
Distribution/release.sh verify /absolute/path/mac-artifact

Choose actual release version/build numbers before packaging; the examples are placeholders. The same settings apply to each embedded app extension. The direct Mac archive exports with developer-id, creates and signs a universal DMG, and stops before any notary upload. The iOS archive exports a local app-store-connect IPA. Both use one artifact engine and record the source commit, Xcode, archive command, version/build, signed identities, entitlements, architectures, provisioning expiration, privacy manifests and matching executable/dSYM UUIDs. Direct inspection also checks Sparkle metadata, its nested updater/helpers, Developer ID certificate team, timestamps and executable Hardened Runtime.

Preserve the whole candidate directory, including artifact.json, archive, export, symbols and logs. The Mac manifest pins the pre-notary/ DMG. Failed attempts are retained and cannot pass verify without completed evidence. Rebuilds create another candidate and require fresh acceptance. Distribution/ExportOptions.plist is a Developer ID reference; the engine records its actual channel-specific export options beside each archive.

Explicit Mac notarization and finalization

These commands contact Apple and use the separately configured VellumNotary Keychain profile. The tool does not create credentials or read their values. Submission sends a private digest-verified copy and records Apple's submission ID immediately. Waiting uses that ID, takes at most 60 seconds per invocation and can be repeated without uploading again. Acceptance requires Apple's notarization log to name the same submission and SHA-256 as the recorded pre-notary DMG.

Distribution/release-macos.sh notary-submit /absolute/path/mac-artifact
Distribution/release-macos.sh notary-wait /absolute/path/mac-artifact
# If needed, repeat notary-wait for the same submission ID.
Distribution/release-macos.sh finalize /absolute/path/mac-artifact
Distribution/release-macos.sh verify /absolute/path/mac-artifact

A submission attempt is recorded before network activity. If transport fails without returning an ID, inspect Apple's notary history through the intended account and recover the existing ID with notary-resume DIRECTORY --submission-id ID. The tool refuses another submit for that candidate. Recovery does not claim acceptance; notary-wait must still verify the remote log and package hash. Always review notary-log.json, including warnings, before continuing.

finalize explicitly downloads/staples the accepted ticket to another private copy, verifies the stapled DMG and Gatekeeper assessment, then runs Sparkle's generate_appcast using the existing Vellum Keychain account. Supply --sparkle-tool /path/to/generate_appcast if the artifact's preserved Swift package tools are unavailable. It verifies the enclosure Ed25519 signature against the exported app's public key without accessing a private key. Whole-feed authentication remains optional; signed update enclosures remain required.

Stapling changes DMG bytes, so final-artifact.json pins a separate final package, signed appcast, and notarization receipt. updates/Vellum-VERSION-BUILD.dmg has a version-specific GitHub enclosure URL; the byte-identical updates/Vellum.dmg alias supports the existing download route. The stable feed is https://vellum.work/updates/appcast.xml. No finalization command publishes an asset.

Explicit promotion of the final Mac bytes

After installation and Sparkle acceptance of this exact final candidate, intentionally publish a tag vVERSION pointing to the manifest's source commit. Tagging/pushing is separate from the release tool. The promote command checks the remote tag, uploads private verified copies of both DMG names and appcast.xml, and marks the new GitHub release latest. It refuses to replace an existing release or reuse a recorded successful promotion.

Distribution/release-macos.sh promote /absolute/path/mac-artifact --notes 'Reviewed release notes'
Distribution/release-macos.sh verify /absolute/path/mac-artifact

The website's stable feed proxy reads the latest GitHub appcast.xml; its Mac download route reads the latest Vellum.dmg. Check those live routes and a clean Mac's downloaded installation/update after promotion; no website deployment is part of this command. A transport failure may have succeeded remotely before the local receipt was written: inspect GitHub assets and hashes before taking any further action. Never clobber a candidate with rebuilt bytes. Keep the previous known-good final DMG, appcast and symbols for incident response; changing the feed does not automatically downgrade installed apps.

Validate and upload the unchanged iOS IPA

These commands contact Apple. Set VELLUM_ASC_PASSWORD to an app-specific password without placing its value in history, logs or source. Supply --provider when needed. Xcode 26.6+ altool resolves the environment reference. altool is restricted to iOS Store artifacts and is never used for Mac notarization.

Distribution/release.sh validate /absolute/path/ios-artifact --username APPLE_ID
Distribution/release.sh upload /absolute/path/ios-artifact --username APPLE_ID

Validation records success after Apple's command succeeds. Upload requires that receipt and verifies the manifest, package, archive and symbols again. Both submit private digest-verified copies and never invoke archive/export. Protect account/transport logs and redact before sharing. Check App Store Connect processing after interrupted delivery before retrying.

Upload is not App Store release. Select the processed iOS build in App Store Connect, stage it with TestFlight, record version/build and acceptance against the artifact digest, then use review/release controls there. Halt a phased release and ship a corrective update for regressions; older builds are not an automatic rollback.

Go/no-go evidence

Attach the artifact digest and actual device/OS/build to each result in release issues. Require two signed devices to prove first cloud sync, offline conflict edits/deletions, eviction/redownload, account change and PDF/annotation/note/attachment/chat continuity. Require Safari sharing, extension termination, oversized-page fallback, widget routing, and cold locked-device integration refresh. Complete VoiceOver, largest text, keyboard navigation, touch/pointer targets, iPad rotation/Split View and the representative PDF/archive corpus. Simulator tests do not close physical-device gates.

Stage the same processed iOS build with TestFlight and the exact final Mac DMG with an isolated test audience; record launch/interaction/memory measurements on supported hardware and unresolved regressions. Release only after blocking issues and review findings are closed with evidence. For incidents, collect app version/build, OS/device class, reproduction steps and redacted diagnostics; request synthetic examples before asking for user documents. Never request tokens, entire libraries, or unredacted conversations by default.
